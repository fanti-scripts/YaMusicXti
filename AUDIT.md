# Аудит мода «Фон Яндекс Музыки»

Дата: 10.11.2026 • Версия Яндекс Музыки: **5.126.1** • Патч: **1.1.0**

Проверено и починено: безопасность, баги, UX. Всё нижеперечисленное **исправлено и
проверено на живой сборке** (патч применялся, приложение запускалось, панель и сервер
тестировались через DevTools-протокол).

## Что проверялось

- Локальный сервер мода (`127.0.0.1:47823`): доступ, токен, CORS, Host, SSRF, доступ к файлам.
- Хранение токена и служебных файлов.
- Движок фона (движок в `index.js`): картинка/GIF/видео, адаптивный режим, слои, затухание.
- Вкладка «Фон» в навбаре и панель настроек (пресеты, слайдеры, «Применить»/«Сбросить», ссылка, папка).
- Поиск, «Моя волна», плеер — как фон уживается со страницами.
- Скрипты `apply.ps1` / `restore.ps1` / `set-background.ps1` и установщик (GUI).
- Цикл «удалить → поставить заново».

## Исправления (безопасность)

1. **Токен больше не лежит на диске.** Раньше `%APPDATA%\YandexMusic\ymbg.token` хранил
   токен в открытом виде. Теперь токен генерируется в памяти при каждом запуске и никуда
   не пишется. Легаси-файл удаляется при установке/запуске. Проверено: файла нет.
2. **Сервер слушает только `127.0.0.1`** и требует заголовок `x-ymbg-token` для
   `/apply` и `/folder`. Проверено: без токена/с неверным токеном — `403`.
3. **Проверка `Host` и `Origin`.** Запросы с чужим `Host` или `Origin` отклоняются (`403`).
   Preflight (`OPTIONS`) без `Origin` — `403`. Разрешён только origin `music-application://desktop`.
4. **Защита от SSRF.** Прямая ссылка на фон: только `http(s)`, только порты `80/443`,
   локальные/приватные адреса (`127.*`, `192.168.*`, `169.254.*` и т.п.) заблокированы.
   Проверено: `127.0.0.1:47823`, `192.168.1.1`, `169.254.169.254` — отказ.
5. **Ограничение доступа к файлам.** `file` может указывать только на файлы в папках
   пользователя (`%APPDATA%`, `%USERPROFILE%`…), только на медиа с разрешённым
   расширением (с 17.11.2026 — любое медиа в папке фонов, см. «галерея „Мои фоны“»).
   Проверено: `C:\Windows\win.ini` и `..\..\` — отказ.
6. **Проверка типа контента** `/apply`: не `application/json` → `415`.
7. **Строгая проверка расширения по содержимому** (`sniffExt`): подмена расширения не пройдёт;
   HEIC/HEIF больше не принимаются за AVIF (проверяется compatible-brand).

## Исправления (баги)

8. **Адаптивный фон включался «на один раз».** Главный найденный баг: таймер опроса обложки
   и `MutationObserver` запускались только при старте приложения, если адаптивный режим был
   включён в конфиге. Если включить его в панели на ходу — фон подхватывал обложку один раз
   и больше не следил за сменой трека. Теперь наблюдатели включаются/выключаются динамически
   (`setAdaptiveWatchers`), а если ничего не играет — показывается пользовательский фон,
   а не пустой экран. Проверено: включение/выключение на ходу и смена обложки.
9. **«Моя волна» ломала панель.** При открытии вкладки «Фон» поверх страницы «Моя волна»
   раскладка ехала. Теперь панель сначала переключает страницу на «Коллекцию» и только потом
   открывается. Проверено: `pathname` → `/collection`, панель открывается.
10. **Шапка поиска** больше не перекрывает фон непрозрачным блоком (правка CSS `SearchPage`).
    Проверено скриншотом страницы поиска.
11. **«Залипший» `exe` при установке.** Служебный процесс Яндекс Музыки (network service) с
    пустым `Path` не находился старым фильтром, файл оставался заблокирован, установка падала
    с `executable is still locked`. Теперь все скрипты используют `Get-MusicProcesses`
    (`Win32_Process` по пути/командной строке + по имени) и ждут разблокировки файла.
    `apply.ps1` теперь корректно ждёт до 30 секунд. Проверено: apply/restore проходят.
12. **Сброс CSS.** Если пользовательский CSS пустой, старый `<style>` очищается (раньше
    оставался висеть).
13. **Ссылка на фон отключает адаптивный режим** перед скачиванием, чтобы скачанный файл
    сразу стал фоном, а не был перебит обложкой.
14. **Бэкапы не затираются.** `fuse_flip.py` не пересоздаёт `.orig`, если байт fuse уже
    выключен; `asar_patch.py` держит бэкап с проверкой версии и патчит всегда от чистой копии —
    повторная установка не портит оригинал. Проверено циклом удалить/поставить.

## UX

- Панель «Фон»: превью, вставка ссылки, drag&drop/выбор файла, «Открыть папку с фонами»,
  пресеты **Стандарт / Мягко / Кино / Стекло**, слайдеры затенения/размытия/яркости/виньетки,
  отдельные «прозрачность/размытие/насыщенность плеера». Проверено.
- Настройки применяются сразу, без перезапуска; «Сбросить» возвращает значения по умолчанию.
- Установщик (GUI): статусы «Всё готово / Готово к установке», версия клиента, состояние патча
  и Python, чекбоксы «запустить после установки» и «стереть настройки при удалении»,
  журнал операций. Кнопки **Установить/Переставить** и **Удалить** проверены вживую.
- Старый WPF-установщик использовал встроенный Python 3.12.10; новый exe 2.0.0 работает без Python.

## Обновление 17.11.2026 — большие видео и обои из ссылки/архива

- **Лимит 80 МБ убран.** Раньше видео целиком уходило в `data:`-URL, отсюда был
  потолок. Теперь файл лежит на диске, а renderer получает его с локального
  сервера: `GET /media?t=<токен>` с поддержкой `Range` (206/416). Проверено:
  ролик **114,5 МБ** (120 с) загружается и играет, `readyState 4`.
- **Загрузка потоком.** `POST /upload` (медиа, лимит 2 ГБ) и `POST /wallpaper`
  (архив/HTML, лимит 1 ГБ) пишут тело запроса сразу в файл, без base64 и без
  раздувания JSON. Ошибка размера — `413` с текстом.
- **Вставка обоев.** Поле «Ссылка на обои, страница или HTML-код» принимает:
  прямую ссылку на файл, ссылку на страницу (ищутся `og:video`, `twitter:player:stream`,
  `<video>`, `<source>`, `<iframe>`, ссылки на `.zip`) и готовый HTML-код.
  Скачивание по-прежнему только на публичные http(s)-адреса, порты 80/443,
  с проверкой каждого редиректа.
- **Wallpaper Engine `.zip`.** Свой мини-распаковщик (stored/deflate):
  `type: video` → видеофайл, `type: web` → папка в `web-wallpaper` и iframe
  через `/web/<токен>/…`, `scene`/`application` → `preview.gif`/`preview.jpg`
  с честной пометкой, что сцену без WE не проиграть.
- **CORS-заголовок `x-ymbg-name`.** Без него preflight отклонял загрузку файлов
  и панель писала «Музыка не отвечает». Добавлен в `Access-Control-Allow-Headers`.
- **Уникальные имена медиа.** `custom-background-<8 hex>.<ext>` вместо
  фиксированного имени — на Windows больше нет «файл занят» при замене фона.
  Старые файлы удаляются best-effort; удаление мода чистит и хешированные имена,
  и папку `web-wallpaper`.
- **Починен плавный переход.** Смена слоя зависела только от
  `requestAnimationFrame`; в перекрытом/свёрнутом окне Chromium его тормозит,
  и новый фон оставался в скрытом слое, а на экране — старый. Добавлен
  таймер-подстраховка (150 мс).
- **Слайдеры больше не перезапускают видео.** `updateAll` сбрасывал
  `currentUrl`, из-за чего любое изменение ползунка пересоздавало слой.
  Теперь адрес сравнивает сам `apply()`.
- **Замена HTML-обоев с тем же именем** перезагружает iframe: в URL добавлена
  метка `?v=<webStamp>`, которая обновляется при каждой установке.

### Ограничения новых функций

- Сцену Wallpaper Engine без самого WE воспроизвести нельзя — только превью.
- Разбор страницы опирается на метаданные/теги; если сайт отдаёт контент
  только через JS, понадобится прямая ссылка или HTML-код.
- Некоторые сайты (например, vsthemes.org) блокируют автоматические запросы —
  скачанный вручную `.zip` при этом работает нормально.

## Обновление 17.11.2026 — галерея «Мои фоны»

- **Галерея фонов.** Панель показывает всё, что лежит в папке фонов
  (`%APPDATA%\YandexMusic`): видео, картинки, `.zip` (Wallpaper Engine) и `.html`.
  Клик по плитке применяет фон. Новые эндпоинты: `GET /library` (список файлов),
  `GET /thumb?t=<токен>&f=<файл>` (превью: картинка/кадр видео/`preview.*` из архива),
  `POST /use` (применить файл из папки), `GET /folder` (открыть папку).
- **Токен в query для медиа.** `/media` и `/thumb` принимают `?t=<токен>`, потому что
  `src` у `<img>`/`<video>`/`<iframe>` не умеет отправлять заголовки. Остальные
  эндпоинты по-прежнему требуют `x-ymbg-token`. Проверено: без токена — `403`.
- **Доступ к файлам расширен осознанно:** `file`/`f` — любое медиа в папке фонов
  с разрешённым расширением (`.jpg/.png/.webp/.gif/.avif/.bmp/.mp4/.webm/.mov/.m4v/.ogv/.zip/.html`),
  с `basename` и проверкой, что путь остаётся внутри папки. Проверено: `..\..\Windows\win.ini` — отказ.
- **Масштаб фона:** Умно (вся картинка + размытая копия по краям), Заполнить, Вписать,
  Растянуть. Смена масштаба перерисовывает кадр, не перезапуская видео.
- **Превью без лишних копий.** Файл, извлечённый из `.zip` (видео или `preview.*` сцены),
  получает имя `custom-background-<sha1 архива>.ext`: повторное применение того же
  архива перезаписывает файл, а не плодит дубликаты в галерее.
- **«Обновить» больше не залипает.** Статус «Обновляю список…» сменялся на
  «Список обновлён»; параллельные запросы списка не игнорируются, устаревший ответ
  отбрасывается по счётчику.

## Известные ограничения

- Ошибки валидации на сервере отдаются кодом `500`, а не `400` — косметика, поведение верное.
- `restore.ps1` намеренно оставляет бэкапы `*.orig` (для повторной установки без пересоздания).
- После автообновления Яндекс Музыки патч нужно поставить заново (файлы клиента перезапишутся).
- Антивирус может относится к модификации `app.asar`/`.exe` настороженно — это нормально для
  подобных модов; установщик всегда позволяет всё вернуть кнопкой «Удалить».

## Как вернуть всё как было

```powershell
powershell -ExecutionPolicy Bypass -File .\restore.ps1
```

или кнопка **Удалить** в установщике.
